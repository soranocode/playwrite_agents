# Планы и запуск тестов

- [Страница руководства: 10 сценариев](raft-guide-test-plan.md)
- [Магазин: 10 сценариев покупки с подменами API](raft-store-test-plan.md)

Все тесты используют проект `chromium` из `playwright.config.ts`.

```powershell
npm run typecheck
npm test
npm run test:ui
npx playwright test tests/raft-store --project=chromium
npx playwright test tests/raft-store --project=chromium --ui --ui-host=127.0.0.1
```

Скрипты `test` и `test:ui` выбирают 20 сценариев в `tests/`. Корневой `seed.spec.ts` остаётся доступен MCP-генератору и планировщику; ограничение `testDir` исключило бы его из поиска. `test:ui` использует IPv4 loopback, обходя наблюдавшуюся блокировку `[::1]`. Ошибки сохраняют trace и screenshot; магазин также прикладывает сетевой журнал. После изменения конфигурации перезапустите уже открытые UI/MCP-серверы, чтобы они перечитали её.

Тесты руководства учитывают клиентский рендер: картинка появляется после загрузки документа и загружается лениво при прокрутке; перед кликами и проверкой адаптивной вёрстки ожидается появление клиентской навигации в DOM. Trigger списка языков и его опция проверяются раздельно, чтобы поле поиска внутри открытого списка не делало локатор неоднозначным.

Тесты магазина открывают настоящий frontend и подменяют авторизацию и создание заказа. Платёжные запросы перехватываются, переход в checkout направлен на тестовую заглушку. Проверяется передача заказа на оплату и обработка ошибок; фактическое списание, выдача предметов и финансовые статусы `paid`/`refunded` в это покрытие не входят.
